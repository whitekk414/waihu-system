# 免费 SIP 自动外呼链路原型设计

## 1. 目标

在不购买 SIM 语音网关、不拨打真实电话号码的前提下，使用开源软件验证自动外呼核心链路：

1. 无登录测试页面创建一条呼叫任务。
2. Java Spring Boot 控制 Asterisk 呼叫测试 SIP 分机。
3. 测试分机接听后，Asterisk 自动播放预先准备的话术并录制双方声音。
4. 挂断后，Spring Boot 获取录音并调用语音转写接口。
5. Spring Boot 调用公司可用的 GPT-5.5 接口完成结构化判断。
6. 测试页面实时显示呼叫、录音、转写和分析状态。

本阶段只验证软件链路。后续接入 VoLTE/SIP 网关时，替换 Asterisk 的外呼线路配置，保留 Java 服务、页面、任务状态、录音处理和模型分析模块。

## 2. 已确认条件

- 服务端和测试页面使用 Java Spring Boot。
- 公司已有服务器资源和 GPT-5.5 模型接口。
- 测试页面不登录，只在本机或测试局域网使用。
- 首版播放固定的预录话术，不实现通话中的动态 AI 多轮对话。
- iQOO Neo8 Pro 可作为测试终端，通过 Wi-Fi 运行 SIP 客户端；也可使用电脑软电话代替。
- 本地设计文档不提交 Git。

## 3. 范围

### 3.1 首版包含

- Asterisk 本地 SIP 服务。
- 一个测试 SIP 分机。
- 单任务创建和自动呼叫。
- 固定话术自动播放。
- 双向通话录音。
- Java 对 Asterisk 的呼叫控制和事件接收。
- 录音文件接收与持久化。
- 可替换的语音转写适配器。
- 可替换的 GPT-5.5 分析适配器。
- SSE 实时状态页面。
- 失败展示和幂等重试。
- 无真实模型凭据时可使用模拟适配器跑通全链路。

### 3.2 首版不包含

- 实体 SIM、真实号码和运营商网络。
- Android SIM 自动拨号 App。
- VoLTE/SIP 硬件网关。
- 实时 ASR、动态决策和 TTS 多轮机器人。
- 批量连续外呼。
- 登录、角色、权限和正式运营后台。
- 公司内部业务系统集成。

## 4. 总体架构

### 4.1 Spring Boot 应用

一个 Spring Boot 进程承载原型业务，内部保持清晰模块边界：

- `task`：创建任务、状态机和查询。
- `telephony`：封装 Asterisk 控制接口，不向业务层暴露 SIP 细节。
- `recording`：定位、登记和校验录音文件。
- `transcription`：封装真实或模拟语音转写服务。
- `analysis`：封装真实或模拟 GPT-5.5 服务，并校验结构化输出。
- `events`：将任务状态通过 SSE 推送给网页。
- `web`：提供无登录测试页面和 REST 接口。

模型地址和密钥只通过服务端环境变量或本地非版本化配置提供，不写入网页。

### 4.2 Asterisk

Asterisk 负责：

- 注册测试 SIP 分机。
- 接受 Spring Boot 发起的呼叫命令。
- 在分机接听后播放指定 WAV 话术。
- 录制完整通话。
- 向 Spring Boot 提供呼叫状态事件。
- 在未来将外呼路由从测试分机切换到 SIM/VoLTE SIP 中继。

首版优先使用 Asterisk REST Interface（ARI）进行呼叫控制和事件订阅。若部署环境中的 ARI 媒体控制不满足需要，电话控制适配器可改用 AMI，但业务接口保持不变。

### 4.3 测试 SIP 终端

iQOO Neo8 Pro 安装 SIP 客户端，通过 Wi-Fi 注册到 Asterisk 的测试分机。测试人员接听后听到自动话术，并口头回答。Asterisk 对本次会话录音。

SIP 客户端只用于测试，不访问 SIM，也不要求 Android 通话录音权限。

### 4.4 实时测试页面

页面提供：

- Asterisk 与测试分机状态。
- 单条呼叫任务创建。
- 话术选择。
- 当前及历史任务列表。
- 呼叫状态时间线。
- 录音文件状态和回放。
- 转写文本。
- GPT-5.5 结构化结果。
- 失败原因和重试操作。

页面通过 SSE 实时更新；SSE 重连后通过 REST 快照补齐状态。

## 5. 核心流程

1. 测试人员启动 Asterisk、Spring Boot 和手机 SIP 客户端。
2. SIP 客户端以测试分机身份注册到 Asterisk。
3. 测试人员在网页选择固定话术并创建任务。
4. Spring Boot 校验分机在线状态，并原子地领取任务。
5. `telephony` 适配器通过 ARI 请求 Asterisk 呼叫测试分机。
6. Asterisk 上报振铃状态；页面显示 `RINGING`。
7. 测试人员接听；Asterisk 上报 `ANSWERED`。
8. Asterisk 开始录音并播放指定话术。
9. 播放结束后保留一段可配置的回答时间，测试人员口头回答。
10. 测试人员挂断，或达到原型配置的最大通话时长后由系统结束测试呼叫。
11. Asterisk 完成录音文件写入，并将文件信息交给 Spring Boot。
12. Spring Boot 校验录音并调用转写适配器。
13. 转写完成后调用 GPT-5.5 分析适配器。
14. 服务端校验模型 JSON，保存结果并标记任务完成。
15. 全部状态通过 SSE 推送到网页。

## 6. 任务状态

- `PENDING`：任务已创建。
- `VALIDATING`：检查 Asterisk、分机和话术。
- `ORIGINATING`：正在发起呼叫。
- `RINGING`：测试分机振铃。
- `ANSWERED`：分机已接听。
- `PLAYING_PROMPT`：正在播放固定话术。
- `WAITING_RESPONSE`：等待测试人员回答。
- `CALL_ENDED`：通话结束。
- `RECORDING_READY`：录音已完成并通过基本校验。
- `TRANSCRIBING`：正在语音转写。
- `ANALYZING`：正在进行 GPT-5.5 判断。
- `COMPLETED`：完整链路成功。
- `FAILED`：失败，并保存错误码、错误信息和失败阶段。

状态机拒绝非法跳转。所有外部调用使用任务 ID 作为幂等键，避免页面重试导致重复呼叫。

## 7. 核心数据

### 7.1 呼叫任务

- 任务 ID。
- 测试分机号。
- 话术 ID。
- 当前状态。
- 创建、呼叫、振铃、接听、挂断和完成时间。
- Asterisk 通道 ID。
- 失败阶段、错误码和重试次数。

### 7.2 话术

- 话术 ID、名称和文字内容。
- Asterisk 可播放的 WAV 文件位置。
- 音频格式、长度和校验值。
- 启用状态。

话术音频统一转换为 Asterisk 兼容格式。原型默认使用单声道、8 kHz、16-bit PCM WAV，以减少转码和兼容问题。

### 7.3 录音

- 录音 ID和任务 ID。
- Asterisk 通道 ID。
- 文件名、格式、大小、时长和校验值。
- 生成时间和保存位置。
- 转写状态。

### 7.4 模型结果

```json
{
  "summary": "本次通话摘要",
  "contact_result": "本人接听/他人接听/无人接听/拒接/号码异常",
  "willingness": "高/中/低/未知",
  "promise_to_pay": false,
  "promised_date": null,
  "dispute": false,
  "risk_flags": [],
  "needs_human_review": true,
  "next_action": "建议下一步操作"
}
```

服务端使用固定 JSON Schema 校验模型响应。非法响应允许一次纠正性重试，仍失败则保留原始响应并标记为可重试失败。

## 8. 测试页面实时状态

SSE 事件至少包含：

- 任务 ID。
- 状态。
- 事件时间。
- 简短说明。
- 可选的进度或错误信息。

页面首次打开和 SSE 重连时先查询任务快照，再订阅增量事件，避免断线期间丢失状态。

## 9. 异常处理

- **Asterisk 不可用**：任务不发起呼叫，显示连接失败。
- **分机未注册**：任务保持失败但允许重新验证，不产生空呼叫。
- **无人接听**：到达振铃超时后结束任务并记录结果。
- **话术文件缺失或格式错误**：拨号前校验并拒绝任务。
- **播放失败**：终止测试呼叫并保留 Asterisk 事件。
- **录音为空或过短**：不调用真实模型，显示录音校验失败。
- **录音处理重复**：使用任务 ID、通道 ID 和文件校验值保证幂等。
- **转写或模型失败**：保留录音和中间结果，使用退避策略重试。
- **SSE 断开**：自动重连并重新加载快照。
- **服务重启**：任务和事件持久化，未完成任务可识别并恢复或明确终止。

## 10. 免费运行边界

Asterisk、Spring Boot 和常见 SIP 客户端均可使用免费开源版本。本地 SIP 呼叫不经过公网电话网络，因此没有真实电话费用。

模型调用是否产生费用取决于公司已有接口。开发和自动化测试默认使用模拟转写与模拟分析适配器；只在端到端验收时切换到真实接口。

## 11. 安全与合规边界

- 测试服务仅绑定本机或受控测试网卡，不开放公网。
- 原型只使用内部测试分机和经授权的测试人员声音。
- 日志不记录密钥，不输出完整敏感文本。
- 录音设置可配置保留期限，并允许手动删除测试数据。
- 接入真实 SIM 和真实客户前，必须完成运营商用途确认以及拨打时段、频率限制、停呼名单、录音告知、人工接管和审计设计。

## 12. 测试策略

### 12.1 单元测试

- 任务状态机。
- 话术格式校验。
- Asterisk 事件到业务状态的映射。
- 录音幂等登记。
- GPT JSON Schema 校验。

### 12.2 集成测试

- 使用模拟 Asterisk 客户端验证呼叫成功、超时和失败。
- 使用模拟转写与模型适配器验证完整处理链路。
- 验证 SSE 断线重连和快照补齐。
- 验证重复创建、重复事件和重复上传不会导致重复呼叫或重复分析。

### 12.3 端到端测试

使用真实 Asterisk 和 SIP 客户端至少连续执行 5 次：

- 正常接听、播放、回答、录音和分析。
- 无人接听超时。
- 分机离线。
- 转写暂时失败后重试成功。
- 模型暂时失败后重试成功。

## 13. 验收标准

- 网页创建任务后，测试分机在数秒内振铃。
- 接听后能清晰听到预录话术。
- 测试人员回答能够进入通话录音。
- 页面无需刷新即可显示主要状态变化。
- 挂断后生成有效录音，并展示转写文本和通过 Schema 校验的 GPT-5.5 结果。
- 失败任务显示明确阶段和原因，并在适用时安全重试。
- 连续 5 次端到端测试中不发生同一任务重复呼叫或结果丢失。

## 14. 后续接入 SIM 网关

免费原型通过后，增加一条 VoLTE/SIP 中继，并把外呼目标从测试分机路由切换为真实号码。保持以下模块不变：

- 测试页面和任务接口。
- Spring Boot 任务状态机。
- Asterisk 控制适配器的业务接口。
- 话术播放、录音、转写和分析模块。
- SSE 事件和结果页面。

接入真实线路时新增：运营商和频段验证、网关健康检查、号码规范化、并发通道控制、真实呼叫结果映射以及正式合规策略。

## 15. 实时 AI 演进

固定话术链路稳定后，再增加独立的实时媒体模块：

1. Asterisk 将通话音频送入实时 ASR。
2. 对话服务根据转写和业务状态调用模型决策。
3. TTS 生成回复并送回 Asterisk 通道。
4. 争议、敏感、低置信度和模型异常场景转人工。

实时媒体模块不会塞进任务或网页模块，从而避免影响已经验证的固定话术与事后分析流程。
