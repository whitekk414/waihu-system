# SenseVoiceSmall + VAD 独立转写接口设计

## 目标

在现有外呼 PoC 旁新增一个完全本地运行的语音转写服务，不依赖 OpenAI API Key。首版只建设独立接口，用已有电话录音验证中文 8 kHz WAV 的识别效果；暂不改造 Java 页面自动调用。

成功标准：

- 服务能在当前 Windows 电脑的 CPU 上启动并完成模型加载。
- 支持上传 WAV 和选择项目 `recordings` 目录中的 WAV 两种调用方式。
- 使用 VAD 排除主要静音片段后，再由 SenseVoiceSmall 转写。
- 对现有非空电话录音返回结构化结果，且不会出现未受控的重复文本。
- 非法格式、越权路径、超限文件和模型异常返回明确的 JSON 错误。

## 方案选择

采用 Python FastAPI + FunASR + SenseVoiceSmall + FSMN-VAD。

选择理由：SenseVoice 与 FunASR/FSMN-VAD 的组合路径直接，中文支持成熟，适合先验证效果；Python 服务与 Java 主应用通过 HTTP 解耦，后续可以替换模型而不改变 Java 业务接口。

首版不采用 sherpa-onnx Java 直连，因为 Windows 原生库和模型打包复杂度更高；不采用 Whisper 双引擎，因为现有短电话录音已出现重复幻觉，增加第二引擎不能保证结果更可靠。

## 服务边界

新服务目录为 `speech-service/`，监听 `127.0.0.1:8090`，不对局域网开放。

组件：

- FastAPI：HTTP 接口、参数校验和错误响应。
- TranscriptionService：统一上传与本地文件的处理流程。
- AudioValidator：校验扩展名、文件头、大小、时长、声道和采样率。
- PathGuard：确保本地路径只能解析到项目 `recordings` 目录内。
- SenseVoiceEngine：单例加载 SenseVoiceSmall 与 FSMN-VAD，执行推理并规范化结果。
- ResultNormalizer：清理模型标签，检测异常重复文本并输出统一结构。

服务不保存上传文件；上传内容写入临时目录，处理完成后删除。本地路径模式只读，不修改源录音。

## API

### 健康检查

`GET /health`

返回服务状态、模型是否就绪和模型名称。模型未就绪时 HTTP 服务仍可响应，但转写请求返回 503。

### 上传转写

`POST /api/v1/transcriptions/upload`

请求为 `multipart/form-data`，字段名 `file`，首版只接受 WAV。

### 本地文件转写

`POST /api/v1/transcriptions/local`

请求示例：

```json
{
  "filename": "1784620809.0.wav"
}
```

`filename` 必须是单个文件名，不接受绝对路径、目录分隔符或 `..`。服务把它解析到配置的 `recordings` 根目录并再次校验解析后的真实路径。

### 成功响应

```json
{
  "text": "识别后的干净文本",
  "rawText": "模型原始文本",
  "language": "zh",
  "emotion": "neutral",
  "segments": [
    {"startMs": 1200, "endMs": 5100, "text": "识别内容"}
  ],
  "audio": {
    "durationMs": 6180,
    "speechDurationMs": 3900,
    "sampleRate": 8000,
    "channels": 1
  },
  "model": "SenseVoiceSmall",
  "elapsedMs": 850
}
```

字段无法可靠获得时使用 `null` 或空数组，不伪造值。SenseVoice 的语言、情绪和音频事件标签会从正文中剥离后单独返回。

## 音频处理流程

1. 接收上传临时文件或解析受限的本地文件。
2. 校验 WAV 文件头、大小、时长和基本音频属性。
3. 必要时在内存/临时文件中转换为模型需要的单声道 16 kHz PCM，不修改原文件。
4. FSMN-VAD 找出有效语音时间段。
5. 对有效片段执行 SenseVoiceSmall 推理。
6. 合并片段、剥离模型标签、规范标点与空白。
7. 检测高比例重复短语；触发时不输出误导性的干净文本，而返回可诊断错误。
8. 返回结构化 JSON，并清理上传临时文件。

VAD 的职责是定位人声而不是区分机器人和客户。当前录音是混合单声道，首版可能同时识别机器人提示音和客户回复；后续应通过 Asterisk 分轨录音从根本上区分双方。

## 安全与限制

- 默认最大文件 20 MB、最大时长 10 分钟。
- 只接受 RIFF/WAVE 音频，不只依赖文件扩展名。
- 本地接口只接受文件名，并限制在 `recordings` 根目录。
- 错误日志不记录音频内容，不泄露系统绝对路径。
- 服务仅绑定回环地址；若未来需要局域网访问，再增加认证与网络策略。

## 错误处理

- `400`：请求字段错误、不是有效 WAV。
- `404`：本地录音不存在。
- `413`：文件或时长超限。
- `422`：没有检测到可识别语音，或结果被判定为异常重复。
- `503`：模型尚未就绪或加载失败。
- `500`：未预期推理错误，响应只返回安全错误码与追踪 ID。

每次响应包含稳定的错误 `code`，便于 Java 后续区分重试与人工检查。

## 测试与验证

- 单元测试：路径穿越、格式/大小限制、标签清理、重复文本检测、错误映射。
- API 测试：上传与本地文件两种请求的成功和失败场景。
- 模型烟雾测试：用 `1784619067.2.wav` 和 `1784620809.0.wav` 运行真实推理，记录原始与清洗结果。
- 人工核验：播放录音并对照转写，不把无法确认的结果标记为通过。
- 性能记录：模型首次加载耗时、单段 6 秒音频推理耗时、峰值内存。
