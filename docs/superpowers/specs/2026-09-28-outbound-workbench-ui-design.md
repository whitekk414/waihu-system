# 外呼工作台 UI 改造设计

## 目标

将现有单页测试界面改造为适合演示与真实操作的专业外呼工作台。视觉上参考 OpenChatCut 的深色、高密度、多面板工作台，但信息架构、文案和交互全部围绕 SIM 智能外呼，不复制对方代码或品牌资产。

## 实现策略

继续使用 Spring Boot 内置的原生 HTML/CSS/JavaScript，不引入 React/Vite 等新构建链。页面直接复用现有 REST API 和 SSE 事件流，保持部署方式不变，把工作集中在可视化与交互体验。

## 页面架构

### 顶部状态栏

- 产品名“CallFlow Studio”和“SIM AI Outbound”副标。
- 展示 Java/SSE 连接状态、当前模式和时间。
- 使用翡翠绿表示在线，琺珀色表示需要注意，红色仅表示失败或危险操作。

### 左侧导航和任务列表

- 导航入口：今日总览、外呼任务、对话记录、系统状态。
- 任务列表显示脱敏号码、状态、创建时间和结果摘要。
- 支持状态筛选、文本搜索、刷新和选中任务。

### 中间实时通话工作区

- 顶部为今日任务、完成、需人工、失败四个指标卡。
- 通话卡显示脱敏号码、当前状态、进度、动态波形和当前话术节点。
- 保留“创建外呼”主操作，打开侧边弹层后输入一个手机号并勾选明确授权。
- “人工接管”和“挂断”在后端尚无对应安全 API 时不伪造功能：显示为未启用并解释原因。

### 右侧 AI 会话面板

- 按轮次显示机器人问题、客户转写、意图、置信度和摘要。
- 使用颜色标签区分已确认、拒绝、不清楚和需人工。
- 无轮次时显示引导空状态，请求失败时显示可重试的明确错误。

### 底部对话时间线

- 将任务事件映射为拨号、振铃、接通、播放、录音、识别、判断、结束等节点。
- 事件展示相对顺序和时间，支持横向滚动，小屏下改为纵向。
- 时间线仅使用真实任务事件，不生成虚假的通话数据。

## 数据流

1. 首页加载 `/api/tasks`，在客户端计算当前任务指标。
2. 选中任务后并行请求 `/api/tasks/{id}`、`/api/events/tasks/{id}` 和 `/api/tasks/{id}/turns`。
3. `/api/events/stream` 接收到 `task-event` 后刷新列表和当前详情。
4. 创建任务依次调用 `POST /api/tasks` 和 `POST /api/tasks/{id}/start-dialog`，后者必须提交 `confirmed:true`。
5. 所有号码只在创建表单内短暂显示完整值，列表和详情统一脱敏。

## 视觉方向

- 深色工业感底色，主色为青绿，蓝紫用于信息层级。
- 使用 CSS 变量建立颜色、间距、圆角和阴影令牌，避免散落的硬编码。
- 使用紧凑但易读的排版，通过进场动画和波形增强演示感，不引入大型动画依赖。
- 桌面端为三栏工作台；小屏转为单栏且保持主操作可见。
- 支持键盘焦点、足够对比度、语义化标签和减少动画偏好。

## 错误与空状态

- API 错误保留后端信息，通过页面内通知条展示，不使用阻塞式 `alert`。
- SSE 断开时显示离线状态并指数退避重连。
- 无任务、无对话和无事件分别提供清晰空状态。
- 拨号失败后保留任务与错误信息，不在前端自动重拨。

## 测试与验收

- 扩展静态页测试，验证工作台主要区域、授权确认和无危险自动拨号。
- 用可控 DOM/API 数据验证指标计算、状态映射、号码脱敏和时间线渲染。
- 运行完整 Maven 测试，并在本地浏览器检查桌面与窄屏布局。
- 页面仍使用真实 API，不在生产页内硬编码伪造指标或通话。

## 提交策略

以真实、可回滚的功能边界创建多个提交：

1. 工作台语义结构与静态测试。
2. 设计令牌、三栏布局与响应式样式。
3. 任务指标、详情、AI 轮次和时间线的真实数据渲染。
4. 拨号弹层、SSE 状态和错误反馈。
5. 浏览器验收、文档和截图。

不伪造历史、不回填日期、不把同一个无法独立验证的改动人为拆成无意义提交。
